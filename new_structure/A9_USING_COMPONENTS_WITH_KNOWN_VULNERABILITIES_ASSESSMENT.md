# A9: Using Components with Known Vulnerabilities - Assessment

## Scope

Identify outdated, loosely pinned, or potentially vulnerable third-party components in the application stack as per OWASP Top 10 (A9). Focus on Python package dependencies defined in `requirements.txt`.

## Methodology

- Manual inspection of `requirements.txt` for: unpinned (>=), wide version ranges, very old versions, security-sensitive libraries.
- Classification: Production vs Development/Test.
- Risk scoring heuristic (High/Medium/Low) based on: library sensitivity, pinning status, known frequent CVEs.

Additional Observations:

- No explicit SBOM (Software Bill of Materials) generation yet.
- No automated dependency vulnerability scan step integrated (e.g., pip-audit, Safety) in tests.
- Redis / Celery / Eventlet pinned—good; these often have security advisories.
- `Flask 2.3.3` is within supported branch; monitor 3.x migration path.

## Risk Detail

- Loose crypto dependency can expose application to timing, padding oracle, or memory corruption fixes missing in older subversions.
- Unpinned DB drivers can introduce subtle behavioral changes (authentication defaults, protocol tweaks) affecting stability and possibly security.
- Lack of automation increases MTTR for emerging CVEs.

## Recommended Actions

1. Pin `cryptography`, `PyMySQL`, `mysql-connector-python` to audited, current patch-level versions.
2. Add automated audit script (`scripts/dependency_audit.py`) optionally invoking `pip-audit` if installed.
3. Add a test to fail build when production dependencies contain unpinned `>=` or unconstrained specs (exclude dev-only section).
4. (Optional) Add SBOM generation (CycloneDX) as a later enhancement.
5. Document remediation and deferrals.

## Out-of-Scope / Deferred

- Transitive dependency deep audit (will rely on pip-audit for that stage).
- Runtime container image CVE scanning (future DevSecOps pipeline step).

## Acceptance Criteria for Remediation

- No production-critical dep specified with only a lower bound.
- New audit script present and runnable.
- Test suite fails if future loose specs reintroduced.
- Documentation describing approach and future improvements.
